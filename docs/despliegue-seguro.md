# Exposición operativa

La demo escucha únicamente en loopback. No está habilitado un dominio productivo ni un certificado en este repositorio. Para publicarla, usar un proxy HTTPS y firewall que permita solo 80/443; mantener PostgreSQL, API, frontend y Mailpit sin exposición directa. El ejemplo [nginx](../deploy/nginx.conf.example) presupone el proxy en el mismo host y requiere dominio/certificados reales; no se ha ejecutado en producción.

Configurar APP_URL y CORS_ORIGIN con el origen HTTPS exacto, NUXT_PUBLIC_API_BASE con https://dominio/api, y conservar NUXT_API_INTERNAL_BASE=http://backend:3000/api para SSR. TRUST_PROXY debe identificar solo el proxy conocido (loopback para este ejemplo); no confiar ciegamente en todos los proxies. El ejemplo reemplaza X-Forwarded-For con la dirección del cliente, sin aceptar una cadena enviada por el visitante. No utilizar el override demo, seed ni proveedor de pagos demo al operar con huéspedes reales.

HSTS se aplica en el proxy TLS, no en HTTP local. Comprobar certificado, redirección, cookies Secure/HttpOnly, CORS, CSP y caché con sesión antes de abrir el firewall. La CSP de documentos permite scripts propios y hashes de scripts internos emitidos por Nuxt; no admite scripts inline genéricos ni eval. Los estilos inline permanecen permitidos porque Vue/Nuxt UI los usan en posicionamiento y temas. Imágenes externas solo images.unsplash.com; conexiones al origen público de API configurado. Las rutas privadas y de acceso usan no-store; assets Nuxt conservan su caché.

Custodiar .env (0600), credenciales administrativas, contraseña de migración y MFA_ENCRYPTION_KEY fuera de Git y separadas del dump. Conservar una copia recuperable de la clave MFA: perderla impide descifrar autenticadores. No rotarla sin un procedimiento de recifrado probado. Los dumps locales están protegidos por permisos pero no cifrados; no transferirlos a almacenamiento externo sin acordar cifrado, destino y custodia/recuperación de claves. La copia externa todavía no está configurada en esta demo.
